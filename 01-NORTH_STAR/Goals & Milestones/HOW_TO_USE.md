# How to Use Goals & Milestones

## Create a goal only when

- the outcome serves the North Star;
- work crosses more than one owner or requires a durable proof bar;
- success can be observed;
- a review date or event exists; and
- Chris has approved the commitment.

## Write the outcome

State what will be true, not everything that might be done. Then name the live
owner, evidence required, review trigger, and decision the result unlocks.

Example:

> By the end of Fall 2026, independently perform the course-level programming
> and physics reasoning required by the registered courses, demonstrated
> through course-permitted work and owner-recorded mastery evidence.

The semester file owns that target. The PYTHON and PHYSICS wikis own the actual
learner frontier. CASTLE selects the next rep. The course systems own grades and
deadlines.

## Review a goal

1. Read the owner evidence.
2. Compare observed proof with the stated bar.
3. Diagnose a miss as access, capability, execution, timing, capacity, market,
   or measurement.
4. Keep, narrow, change, park, or close the goal.
5. Record Chris's approval for a material change.
6. Return only the changed target or status here.

## Keep the layers separate

- Permanent direction → `..\NORTH_STAR.md`
- Adaptive outcome → this folder
- Sequencing and next action → CASTLE and `NOW.md`
- Domain truth → owning wiki
- Build evidence → owning project
- Review history → `00-BRAIN\Session_Logs\`

## Learning Contract

1. Start with the system map: what this is, where it sits, what flows into it, and why it matters.
2. Give a small skeleton, example, or first constraint before asking for open-ended production.
3. Teach through conversation and real work; avoid replacing instruction with a documentation dump.
4. Define new terms precisely. Use them immediately, then retrieve them again later in a different context.
5. Use construction, tools, movement, diagrams, and spatial relationships when they clarify—not as forced decoration.
6. Explain the reason behind formulas and procedures so patterns have meaning.
7. Check understanding through explanation or application, not a nod.
8. Increase independence as the frame becomes familiar. Scaffolding is temporary support, not permanent control.

## Decision and Execution Contract

- Distinguish **exploration**, **decision**, and **execution**. A brainstorm is not a commitment.

- Present the strongest recommendation with evidence, tradeoffs, and a disconfirmation condition.
- Surface displacement cost: what this choice delays or consumes.
- Use outlines, checklists, diagrams, templates, and worked starts for unfamiliar sequences.

## Predictable Failure Modes and Countermeasures

| Risk | Countermeasure |
|---|---|
| Many valuable ideas compete with the active outcome | Capture, rank by evidence and displacement, then return to the chosen deliverable |
| A long-range goal nears completion and momentum falls | Define the next horizon early and mark interim wins without manufacturing a new project |
| An unfamiliar task begins from a blank page | Supply a starter map, example, outline, or skeleton |
| Arbitrary terms or formulas fade | Use precise meaning, application, written cues, and later retrieval |
| Strong vocabulary outruns the audience | Translate to the simplest precise version and test reception |
| Visual scanning gets spent on low-value polish | Set a quality threshold and reserve deep QA for consequential work |
| Pattern confidence gets ahead of evidence | State assumptions, test alternatives, and identify disconfirming evidence |
| Team energy turns into dependence on feedback | Use collaboration to orient, then return ownership and require an independent rep |
| Planning becomes schedule control | Show fixed constraints and consequences; scope to declared capacity; leave timing to Chris |
| System-building substitutes for using the system | Demand a tangible output or decision from architecture work |

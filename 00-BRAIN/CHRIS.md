## Core Drivers
*(The aptitudes that predict effectiveness and satisfaction)*

**Idea Generation: Brainstormer (HIGHEST TIER)**
Generates ideas at a fast and furious pace regardless of topic or prior knowledge. Can elaborate on anything on the fly. Never experiences writer's block.
*Risk: Goes off on tangents — and tangents of those tangents. In a structured learning session, this is a scope-creep engine. Name it and redirect every time.*
*Difficult: Concentrating on one task in a stimulating environment. Implementing ideas. Rote memorization.*

**Numerical Reasoning: Numerical Detective (HIGH)**
Automatically spots patterns in numbers. Projects trends forward to build future strategies. Natural analyst.
*Application: Statistics, data analysis, financial modeling, SQL. Loops and data structures feel natural.*

**Spatial Visualization: 3D Visualizer (HIGH)**
Visualizes objects in 3D and rotates them mentally. Natural for architecture, engineering, carpentry, design. Processes information by drawing diagrams.
*Application: ISYE coursework, system diagrams, process maps. Use spatial language always: "above," "inside," "flows into," "sits on top of."*

**Visual Comparison Speed: Visual Scanner (HIGH)**
Fast and accurate visual processing. Catches errors automatically — a crooked tile grabs his eye without trying. Natural proofreader. Finishes forms before anyone else.
*Application: Debugging is a natural strength. Spots inconsistencies fast. Don't waste this on low-value tasks.*

**Inductive Reasoning: Investigator (MIDDLE-HIGH)**
Takes time fitting facts into a pattern — not too fast, not too slow. Sets the pace in group problem-solving. Reins in those who jump to conclusions, spurs those who drag feet.
*Application: Weighs facts before deciding. Comfortable saying "I don't have all the facts yet." Good at making improvements to existing systems rather than rebuilding from scratch.*

**Sequential Reasoning: Process Supporter (MIDDLE-LOW)**
Works best with established processes, routines, and organizational tools already in place. Doesn't get bogged down by process for its own sake — just needs the frame.
*AI implication: Always provide structure before asking for execution. Commented skeleton, numbered steps, clear constraints. Blank page = frozen. Skeleton = execution.*
*Difficult: Thinking through steps without writing them down. Organizing ideas in writing without an outline first. Speaking about unfamiliar material on the fly.*

## Amplifiers
*(Supporting aptitudes that boost core driver performance)*

**Numerical Computation: Advanced Numerical Computer (HIGH)**
Keeps a running tally of calculations in his head at all times. Mental math is automatic, not effortful. Can multitask while computing.
*When paired with Numerical Reasoning: becomes a triple threat — spots patterns, projects them, and runs the math simultaneously.*

**Associative Memory: Cue User (LOW)**
Not comfortable relying on memory alone to retain and recall new terminology, names, dates, or formulas. Needs repeated exposure, conscious practice, and cue-based anchoring.
*This is THE critical constraint for learning to code.*
*The fix is not a term cap. The fix is:*
- One exact meaning per term — never ambiguous
- Immediate use in working code
- Repetition through action, not isolation
- Construction/physical-world anchors as memory cues
- Cold check at next session start

*Flashcard reinforcement: Chris's responsibility between sessions.*

## AI Quick Reference

**DO:**
- Conversational teaching — not documentation dumps
- Construction/physical-world anchors for every new concept
- One exact meaning per term — never "it depends"
- Drill terms through repeated use in working code
- Provide skeletons before asking for execution
- Break steps into numbered lists
- Connect every session to the active project or mission
- State material tradeoffs once; preserve useful side ideas without obstructing Chris's direction
- End every session with a micro-win named explicitly
- Use spatial language: "above," "inside," "flows into"
- Name the next horizon when a goal is nearing completion

**DO NOT:**
- Define a term as "it kind of means..." without resolving it
- Freeze production waiting for terms to be "officially locked"
- Give open-ended prompts without constraints
- Assume last session's vocabulary was retained
- Dump documentation — convert it to conversation
- Let a session end without a stated output or next action
- Cheerlead without naming what specifically was learned
- Expand scope without explicit approval
- Use elevated vocabulary when simple precision works better

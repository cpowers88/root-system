# Weekly Plan — July 27 to August 2, 2026
### Full-course-load simulation · Chris's execution checklist · set directly by Chris

This is a compressed school-week simulation, not a claim that 20 hours equals the
full Fall workload. It uses twenty focused academic blocks of about one hour each
so the planned percentages become visible and testable. Breaks and setup time are
outside the block count.

## Main Weekly Goal

Complete one honest simulation of the registered Fall course mix while making real
progress in Python functions and Physics projectile motion, beginning TCOM reading
ahead, lightly previewing Economics, and keeping ENGR orientation-only until the
real Fall source exists.

## Allocation

| Course lane | Share | Blocks | Weekly outcome |
|---|---:|---:|---|
| CSE 1321 + Lab / Python | **40%** | **8** | Close any remaining Stage 3 gate, then run the Stage 4 **functions** lecture/lab/assignment/quiz/cold-read cycle (libraries are Stage 4b, not this week) |
| PHYS 2211 | **30%** | **6** | Advance Stage 4 from conceptual projectile-motion reading into one cold independent solution |
| TCOM 2010 | **15%** | **3** | Read and map the Week 1–2 foundations: technical communication, email/memo structure, ethics, and audience |

| ECON 1000 | **5%** | **1** | Light Week 1 foundations preview and explain-back |
| **Total** | **100%** | **20** | Four focused blocks Monday–Friday |

Chris may move blocks between days around family and real commitments. Preserve
the **8/6/3/2/1 weekly totals** unless capacity drops. If capacity drops, cut ENGR
orientation block 2 first, then TCOM block 3; do not cut the Python or Physics
proof blocks.

## Fixed / Non-Negotiable This Week

- All practice is fresh, private, pre-semester work—not a live graded submission.
- CSE 1321/1321L: no AI-assisted submitted work.
- TCOM: AI does not draft assignments; this week is reading, analysis, and Chris's
  own explain-back only.
- ENGR: use the restrictive no-AI boundary until the exact Fall BWD policy exists.
- Sunday, August 2: close plan versus actual and generate the next weekly plan.
- Optional architecture, metadata, wording, and cleanup work does not interrupt an
  academic block unless it is a HIGH blocker or Chris directly changes priority.

## Day-by-Day

### Monday, July 27 — Enter the Week

- [ ] **Python 1 — Gate check / Stage 4 baseline** — If Sunday's review did not
  close Stage 3, complete one fresh loop-and-accumulator build from plain English
  with no hints and explain every state change. If Stage 3 is closed, use the
  block for a cold baseline: define and call one simple function, then explain
  parameter, argument, and return value. *(~1 block)*
- [ ] **Python 2 — Functions lecture** — Read the Stage 4 local map and the
  `defining-and-calling-functions`, parameters/arguments, and return-value
  sections. Spine reading is **Think Python physical pp. 43–52 and 83–87** — about
  15 pages, exact pages in `PYTHON/wiki/source-page-map.md`. Close the material and
  explain: input enters through parameters, work happens in the body, output leaves
  through `return`. *(~1 block)*
- [ ] **Physics 1 — Projectile-motion model** — Read the Stage 4 overview and
  projectile-motion concept page. Draw the physical system and explain why
  horizontal and vertical motion can be analyzed independently while time connects
  them. No equation hunting before the diagram. *(~1 block)*
- [ ] **TCOM 1 — Course and document map** — Review the TCOM semester map, then
  read the assigned textbook material on emails and memos (Open TC Ch. 2.13).
  In Chris's own notes, identify audience, purpose, subject line, opening,
  organization, and requested action. *(~1 block)*

### Tuesday, July 28 — Lab Day

- [ ] **Python 3 — Function-writing lab A** — Open `drills/stage-04-function-writing`
  and do its **Cold-Read Gate** plus the first two functions from a blank file:
  `fahrenheit_to_celsius(f)` and `is_even(n)`, both of which must `return`, not
  print. Write all three signatures and a one-line return/print contract *before*
  filling any body. Predict each output before running. *(~1 block)*
- [ ] **Python 4 — Function-writing lab B** — Finish the drill: `shout(message)`
  (the void one — be able to say why it needs no `return`), then the calling code
  that uses all three, then the three Self-Check questions on scope. Log the first
  real error class if one occurs; retry from memory after reading only the matching
  section. *(~1 block)*
- [ ] **Physics 2 — Read the equations physically** — Work through the Stage 4
  projectile equations. For each term, state what it measures, its units, its
  sign convention, and what the graph would look like. Connect \(v_x\) to constant
  horizontal motion and \(a_y\) to gravity. *(~1 block)*
- [ ] **ENGR 1 — Source and logistics orientation** — Confirm that the registered
  section remains BWD and that only the Summer W01 reference syllabus is available.
  Record questions the real syllabus must answer: delivery format, instructor,
  required work, grading, attendance, deadlines, and AI policy. Do not use the
  Summer schedule as a Fall plan. *(~1 block)*

### Wednesday, July 29 — Assignment Day

- [ ] **Python 5 — Function Toolbox, design pass** — Start the Stage 4 mini-project.
  Write Chris's own plain-language requirements and pseudocode first. Choose small
  functions with clear names, parameters, and return values; add docstrings while
  the design is visible. *(~1 block)*
- [ ] **Python 6 — Function Toolbox, implementation pass** — Implement and test the
  mini-project independently. Use several inputs, including one boundary case.
  Explain why each function returns a value or deliberately does not. *(~1 block)*
- [ ] **Physics 3 — Covered-example reconstruction** — Study the projectile-cliff
  example once, cover it, redraw the situation, list knowns/unknowns, select the
  model, and reconstruct the solution without copying its sequence. *(~1 block)*
- [ ] **Physics 4 — Fresh projectile drill** — Complete one fresh horizontal-launch
  or angled-launch problem from the Stage 4 drill. Include diagram, component
  equations, units, numerical result, and a reasonableness check. *(~1 block)*

### Thursday, July 30 — Retrieval and Reading Day

- [ ] **Python 7 — Closed-book quiz** — Use the Stage 4 functions flashcards with
  notes closed. Define and distinguish function, call, parameter, argument, local
  variable, scope, and return value. Reopen only failed items, then repeat them
  closed-book. *(~1 block)*
- [ ] **Physics 5 — Representation transfer** — Take one projectile situation and
  move among words, diagram, component table, equations, and motion graphs. Explain
  what changing launch speed or height changes and what it does not. *(~1 block)*
- [ ] **TCOM 2 — Ethics and audience reading** — Read Open TC Ch. 3 ethics and the
  mapped Week 1 ethics examples. Then preview the Week 2 audience-analysis section.
  Chris records the difference between a legal choice, an ethical choice, and an
  audience-effective choice. No assignment drafting. *(~1 block)*
- [ ] **ECON 1 — Foundations preview** — Read the confirmed Week 1 foundations
  material using the mapped OpenStax Ch. 1 or CORE Unit 1 substitute. Close it and
  explain scarcity, incentives, opportunity cost, and one tradeoff using a real
  household, construction, or business example. This is orientation, not deep
  macro study. *(~1 block)*

### Friday, July 31 — Proof Day

- [ ] **Python 8 — Cold read and Stage 4 proof attempt** — Take one unseen short
  functions program. Locate calls and definitions, trace parameters and local
  state, predict output, then run it and explain any gap. Finish with one small
  function built cold from plain English. Record evidence; advance learner truth
  only if the Stage 4 gate actually passes. **Stage 4 is functions only** — the
  standard-library bridge is now its own stage
  (`stages/stage-04b-python-libraries`, course Module 4) and is *not* part of this
  week's gate. *(~1 block)*
- [ ] **Physics 6 — Cold Stage 4 checkpoint** — Solve one fresh projectile problem
  with no worked example open. Required evidence: situation classification,
  diagram, knowns/unknowns, x/y model, units, solution, reasonableness check, and
  explain-back. A miss becomes the exact starting point next week. *(~1 block)*
- [ ] **TCOM 3 — Structure explain-back** — Compare one poor and one improved
  business-message example from the mapped resources. With sources closed, Chris
  explains what changed in audience fit, organization, tone, readability, and
  action clarity. Record only a reading/craft note—not draft coursework. *(~1 block)*
- [ ] **ENGR 2 — One-credit-course simulation** — Perform a bounded readiness
  block: check whether the exact Fall syllabus has appeared; if not, organize the
  unanswered course questions and rehearse the weekly operating habit this course
  is likely to require—open requirements, identify the independent task, complete
  it without AI assistance, and record completion. No content or grading assumptions
  from the Summer section. *(~1 block)*

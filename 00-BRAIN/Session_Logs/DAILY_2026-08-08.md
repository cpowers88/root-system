## Chris's design intent for `tree`, stated directly — recorded verbatim in substance

Not previously written anywhere in `.ROOT`. This is the controlling statement of
what `tree` is for:

- `.tree` is a **completely new folder**. `.ROOT` sits beside it and stays live
  while `tree` gets off the ground.
- `tree`'s first job is to **ingest how to build an AI frontman operating
  system** — that is the seed content, not general note storage.
- **`.md` files are the main instruction set.** Python where applicable.
- **A wiki folder structure guides everything.** The first layer is a *wiki of
  wikis*; wikis nest inside it with progressively more specific instructions.
- There must be a **callable, usable structure invocable from the terminal**,
  taking a question about any material in the main folder.
- It should live **inside an Obsidian vault** — easier to manage, and consistent
  with the git repos reviewed.
- **Design the complete structure first.** "An upgraded folder structure made
  right the first time, which is why all the planning."

**Consequence for the two proposed governance files:** neither `ROOT.md` nor
`SYSTEM.md` specifies this system. Terminal callability appears nowhere; the
wiki-of-wikis appears as one table row ("Indexes — search and relationship
acceleration"); `.md`-as-instruction-set is never stated as a design choice;
Obsidian is absent; the Python boundary is one undefined "Runtime" row. They are
a competent constitution for a filing system and do not describe the product.

**Sequencing finding:** Codex began at the last step. A constitution encodes
decisions already made; these were written before the decisions exist, which is
why they are generic. Recommended design order: (1) retrieval contract → (2) page
contract → (3) wiki contract → (4) generated routing layer → (5) folder tree →
(6) governance. Step 1 is load-bearing: terminal-answerability dictates page
metadata, which dictates what a wiki is, which dictates the tree.

**Architecture recommendation made, not decided:** `tree ask "…"` should
**assemble, not answer** — Python resolves the route from a generated index and
emits the exact file set plus a grounded prompt for the agent that already has the
vault open. Rejected local RAG/embeddings for v1: adds a vector store, an
embedding model, and a silently-staling re-index; breaks local-first the moment
the embedding model is hosted; and is unfalsifiable when it returns the wrong
chunk. Deterministic and inspectable now; embeddings are an additive v2 if
index-plus-grep provably fails.

**Obsidian constraint with teeth:** Obsidian resolves `[[wikilinks]]` by filename
vault-wide, so duplicate basenames across wikis break linking silently. `.ROOT`
already has this (`CLAUDE.md`, `index.md`, `log.md` repeated per hub) and tolerates
it because nothing depends on link resolution. In `tree`, where a router walks
relationships, it is a correctness bug. Forces a naming decision **before any
folder exists**: globally unique basenames, or short names plus mandatory
path-qualified links. Separately, dot-prefixed *subfolders* are invisible to
Obsidian's indexer, so no content folder may be dotted — the vault root itself is
fine either way, so this is not an argument for `tree` over `.tree`.

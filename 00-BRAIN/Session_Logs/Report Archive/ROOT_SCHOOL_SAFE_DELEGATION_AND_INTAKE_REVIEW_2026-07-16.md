## Delegation Order

### 1. Evidence packaging and verification

This is the highest-return autonomous lane. Give AI a completed source, observation,
or project output and ask it to reconcile claims, update the owning evidence home,
produce the smallest reusable asset, run deterministic checks, and return the next
human decision. It advances the system without stealing the proof rep.

### 2. Triggered source intake

Use chunk ingestion only when a source answers an active decision or closes a named
retrieval gap. The July 16 AGC construction outlook passed that test and was ingested
because it directly sharpens the construction observation. The following do not
justify automatic compilation merely because they remain in `raw/`:

- SYSTEMS: *Algorithms to Live By*, *Learning to See*, and `TLS.pdf` remain behind
  their recorded decision or real-deliverable triggers.
- AI_AUTOMATION_SYSTEMS: the remaining *Empire of AI* parts are a lower-priority
  investigative backlog; *If Anyone Builds It, Everyone Dies* stays a challenge
  source until a concrete safety review needs it; *Mastering Claude AI* requires
  current official-doc verification before use.
- TECHNOLOGY: the raw folder is accounted for; DDD and UX should reopen only for a
  real architecture or interface decision.
- BUSINESS: more general books and templates are lower value than one live workflow
  observation.

### 3. Watchtower sweep

Run one bounded weekly scan of official/primary sources tied to active choices: AI
agent platforms, the active data/automation stack, construction and real-estate
operating conditions, regulation/security, and KSU/ISYE-adjacent technology. A
finding enters `radar.md` only after it has an owning evidence page, material
consequence, and review trigger. General news and capability announcements stay out.

The July 16 sweep produced one qualifying WATCHING signal: AGC's year-over-year
construction AI-adoption increase. OpenAI's July 9 ChatGPT Work release was reviewed
but not promoted because `.ROOT` already documents and uses delegated, long-running
agent work; it did not change an active choice in this review.

### 4. Maintenance with a proof return

The July 24-26 `check_at` outcomes, weekly wiki sweep, ledger completeness, stale
dashboard check, and inbox routing are valid delegated maintenance. Do not reopen
architecture from aesthetics or file-count anxiety. Record an observed outcome,
keep/modify/revert verdict, and exact next trigger.

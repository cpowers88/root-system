  ## Is there a folder-wide output format?

  There are three partial standards, but not one complete folder-wide artifact format.

  ### What is standardized

  1. Physical format:
      - Markdown is the default written format.
      - Frontmatter is expected to carry type, timeline, tags, and relevant optional properties.

  2. Operational return:

     Every meaningful operation is supposed to return the canonical five-field Return Packet:
      - Outcome
      - Evidence link
      - Capability/status movement
      - Reusable-asset candidate
      - System-learning candidate

  3. Wiki machine shell:

     All eight hubs now have:
      - CLAUDE.md — machine loader
      - OPERATIONS.md — canonical machine contract
      - README.md — short human entrance
      - HOW_TO_USE.md — human workflow
      - wiki/index.md — catalog
      - wiki/log.md — operational history

  ### What is not standardized

  There is no common machine-readable declaration in every hub answering:

  - What exact artifact types may this hub produce?
  - Which file is canonical for each output?
  - What minimum fields must each output contain?
  - What proof distinguishes a finished output from generated preparation?
  - Where does each output return?

  Only BUSINESS has an explicit general “Page contract.” Python and Physics have detailed authoring standards and
  templates. The other five hubs mostly define outputs indirectly through prose.

  This is the largest legitimate tuning opportunity. I would not force every wiki page into one body template. I would
  standardize the output envelope while keeping domain-specific bodies.

  A proposed hub output declaration should contain:

  Owned input
  Transformation
  Stored output
  Proof output
  Canonical owner
  Required return

  That gives every machine the same questions without pretending a Physics drill, Technology lookup, and Revenue Lab
  scorecard should look alike.

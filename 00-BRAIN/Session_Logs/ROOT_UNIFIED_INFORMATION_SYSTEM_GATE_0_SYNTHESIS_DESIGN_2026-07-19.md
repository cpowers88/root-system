## Target Architecture

Five layers. Only the flow view is new, and it enters as a diagnostic
overlay, not governance. Construction anchor: the building (canonical truth)
and its structural system (System Loop) do not change; we are testing whether
a load-path diagram on the cover sheet makes the plan set readable before
deciding to re-issue the drawings.

```text
LAYER 5  AI CONTEXT       bounded task packs (manual; atlas-brief pattern)
LAYER 4  INTERFACE        START_HERE cockpit · derivative Canvas · Base (only
                          after a proven query) — points to owners, never copies
LAYER 3  FLOW VIEW        the seven-line trace (diagnostic overlay, per item)
LAYER 2  LIFECYCLE        System Loop (only canonical lifecycle) · five moves =
                          task protocol · cadence = when review happens
LAYER 1  CANONICAL TRUTH  realms, raw, owners, Git — physically frozen
```

The seven-line trace (Layer 3) is the entire pilot vocabulary:

```text
1. Intent        — question/outcome, owner, authority boundary
2. Source/Trust  — where it came from; what makes it trustworthy
3. State         — where canonical truth lives right now
4. Loop stage    — which System Loop stage this is (existing vocabulary)
5. Next action   — the one next transformation, and its approval boundary
6. Proof         — the evidence that will count, and who accepts it
7. Return        — the file/owner the outcome evidence returns to
```

This keeps the only two concepts the existing contracts genuinely lack —
**intent** and **trust/provenance** — and borrows everything else from the
System Loop instead of installing eight parallel stages.

## Trade-off Analysis

**Pilot-first vs. contract-first.** Cost: if promotion is eventually needed,
we reach the unified contract one to two weeks later than Codex's sequence.
Gain: the contract, if written, is shaped by two real traces instead of
theory, and if not needed, roughly 10–20 hours of contract, shell, module
audit, and migration work never happens. In a one-operator system where time
is the binding constraint, the asymmetry strongly favors pilot-first.

**Seven-line trace vs. eight-stage vocabulary.** Cost: less expressive; no
planes. Gain: zero new terms to memorize (matters given the associative-memory
constraint — one exact meaning per term, reused from existing contracts), and
it cannot become a fifth loop because five of its seven lines are pointers to
existing vocabulary.

**Trace inside the Bootcamp vs. pausing the Bootcamp.** Cost: the pilot
shares attention with the sprint. Gain: the contractor case stays live, the
technology rep is preserved, and the architecture is tested on real moving
work instead of a staged example — which is the only test that counts.

**Fixing promotion criteria now vs. deciding later.** Cost: less flexibility.
Gain: prevents the known failure mode of this vault — re-opening the
architecture question each time a new report arrives. The criteria are the
ratchet.

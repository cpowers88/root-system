## The Method in One Sentence

Follow the work, not the org chart — watch what actually happens,
write down where time and money leak, and leave with enough specifics
to write a report the owner can act on Monday morning.

---

## BEFORE THE VISIT (30 min prep, night before)

- [ ] What does this business sell, and who pays them?
- [ ] Guess the 3 core workflows before arriving (intake → work → get paid
      is the universal spine). You'll correct the guess on-site.
- [ ] Know the tool categories cold — review the 12 categories in
      TECHNOLOGY_LIBRARY_STRATEGY.md so you can name what you see.
- [ ] Decide the ONE question this visit must answer:
      "Where does this operation lose the most time or money?"
- [ ] Pack: notebook + phone (photos of whiteboards, forms, paper piles —
      ask first). Nothing else. No laptop on the first walk.

## DURING THE VISIT — What to Watch For

### Follow one job through the system
Pick one real job/order/customer and trace it start to finish.
Every handoff it crosses is a place waste hides.

### The Three Systems Questions (ask them about every step)
```
Where does state live?      (head, paper, text thread, spreadsheet, system?)
Where does feedback live?   (how do they KNOW it worked / got done / got paid?)
What breaks if I delete this? (person, tool, or step — what's load-bearing?)
```

### The Waste Checklist (tally every sighting)
- [ ] WAITING — work sitting idle between steps
- [ ] DOUBLE ENTRY — same data typed into two places
- [ ] REWORK — anything done twice because it was wrong the first time
- [ ] TRIBAL KNOWLEDGE — "only Mike knows how" moments
- [ ] MANUAL HANDOFF — a human carrying information a system should carry
- [ ] SPREADSHEET-AS-DATABASE — one giant file everyone edits
- [ ] TEXT/EMAIL AS SYSTEM OF RECORD — decisions living in threads
- [ ] MISSING FEEDBACK — nobody can answer "how do you know?"
- [ ] SHADOW SYSTEMS — the unofficial notebook/whiteboard that's the REAL system

### What to write down (specifics sell, generalities don't)
- Times: how long the wait actually was, how long the retyping took
- Counts: how many times per day/week this happens
- Quotes: what workers say verbatim ("I spend every Friday afternoon on…")
- Roles only, never names, in anything that leaves your notebook

### How to behave
- Watch first, ask second. Questions change behavior — observe the
  unperformed version before you make people self-conscious.
- Ask "can you show me?" not "can you tell me?" — the walkthrough
  always reveals what the description hides.
- Never propose fixes on-site. You're there to see, not to sell.
  The report is the deliverable; premature advice is free consulting.

## AFTER THE VISIT (same day, within 4 hours — memory decays fast)

1. Brain-dump everything into FIELDNOTES_DATE_TOPIC.md
   (→ 05-BUSINESS\02-Field Notes\, template exists)
2. Draw the process map — boxes and arrows, one page, the job's real path
3. Fill the friction inventory: each waste sighting → time cost/week estimate
4. Sort findings on the Recommendation Ladder (TECHNOLOGY_LIBRARY_STRATEGY.md):
   eliminate → simplify → use what they own → configure → integrate → build
5. Draft the one-pager (ONE_PAGE_FINDINGS_FORMAT.md) — owner language, numbers first
6. Full report only if the engagement calls for it (TECHNOLOGY_AUDIT_REPORT_TEMPLATE.md)

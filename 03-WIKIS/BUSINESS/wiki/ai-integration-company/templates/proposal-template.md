# Proposal Template

For quoting projects (Rungs 2–3 of the [[service-offer-ladder|Service Offer Ladder]]). Short — 2–4 pages. A proposal is a decision document, not a brochure: the client should be able to say yes in one read. Sent within 48 hours of the conversation that prompted it, never quoted live ([[pricing-models|Pricing Models]] rule 2).

---

# [Project Name — outcome-flavored, e.g., "Quote Turnaround System"]
**Prepared for:** [Name, Company] · **Prepared by:** · **Date:** · **Valid until:** [+30 days]

## 1. The Problem (their words, your numbers)
*3–5 sentences. Restate the pain using their own phrasing from the audit/discovery, then the quantified cost:*

> [Company]'s [process] currently requires [X hours/week] of manual work across [roles], costing approximately **$[X]/year** in labor, plus [error/leakage consequence]. [If from an audit: "Full analysis: Audit Findings #2 and #5."]

## 2. The Outcome
*What will be true when this is done — measurable, not technical:*
- [Metric 1]: from [current] → [target] (e.g., quote turnaround: 2 days → 2 hours)
- [Metric 2]: [X] hours/week of manual work eliminated
- [Metric 3]: every [lead/invoice/document] tracked — nothing falls through

## 3. What We'll Build
*3–6 plain-language bullets. Name workflows, not vendors. The "how" details live in the SOW.*
- When [trigger], the system will automatically [action], and [person] will [remaining human step]
- ...
- Monitoring and failure alerts on everything built — if something breaks, we know before you do

**Not included:** *2–4 explicit exclusions. This line prevents 80% of scope disputes.*

## 4. Investment

| | |
|---|---|
| [Project name] | **$[X], fixed fee** |
| Payment | 50% to begin · 50% at delivery *(40/30/30 above ~$15K)* |
| Timeline | [X] weeks from kickoff |
| Includes | Build, testing with your real data, staff training, documentation, 30 days post-launch support |
| Third-party software | ~$[X]/mo, billed to your accounts directly (itemized in SOW) |

**Payback:** at the documented cost of $[X]/yr, this system pays for itself in approximately **[X] weeks**.

## 5. How It Works
1. Kickoff + access setup (week 1) — we'll need [specific access/data/people]
2. Build + weekly progress updates
3. Testing against your real historical data; you approve before anything goes live
4. Parallel run alongside the current process for [1–2 weeks]
5. Cutover, training, documentation, handoff

## 6. Proof
*One relevant [[case-study-template|case study]] in 3 sentences + the metric table. If pre-proof: one honest paragraph on your method and the audit rigor they've already experienced.*

## 7. To Proceed
Sign below / reply "approved" and I'll send the kickoff agenda and invoice for the deposit. Start date: **[date]** (next available: [date+X] if this window passes).

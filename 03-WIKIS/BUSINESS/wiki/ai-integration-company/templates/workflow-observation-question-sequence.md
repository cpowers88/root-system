# Workflow Observation Question Sequence

> A fill-in worksheet for the first 45-60 minute workflow session. Ask in this
> order. Stay with one recent event, observe before proposing, and leave with a
> measurable consequence plus one concrete next commitment.

Method: [[../first-workflow-observation-field-plan|First Workflow Observation
Field Plan]]. This is a discovery and observation worksheet, not the intake form
for a signed full audit.

## Evidence Priority

The most valuable information is not an opinion about AI. Collect evidence in
this order:

1. **A recent real event** that can be reconstructed.
2. **A live or artifact-supported workflow** from trigger to outcome.
3. **A repeated friction point** with frequency, active time, waiting, or errors.
4. **An operational or economic consequence** tied to that friction.
5. **The owner of the workflow and decision** needed to change it.
6. **Prior effort, spend, or workarounds** proving the pain already motivates action.
7. **A dated advancement commitment** proving the conversation changed the state
   of the opportunity.

Compliments, AI ideas, hypothetical interest, and feature requests come after
these and do not replace them.

## Before the Session: Define the Test

Fill this without the participant:

```text
Date:
Participant role:
Segment: real estate / small construction / medium construction / other
Candidate workflow:
Why this workflow may matter:

Assumption 1:
Assumption 2:
Assumption 3:

Answer that would kill or park this opportunity:
Best next commitment to request:
```

Do not enter the session with more than three assumptions. Your job is to test
them, not defend them.

## Step 1: Permission and Boundary (Minutes 0-3)

Say:

> I want to understand one real workflow, not evaluate you or pitch a tool. I
> will ask you to show a recent safe example, separate facts from estimates, and
> send you a short map to correct. Is that okay? What information should I not
> view, record, or retain?

Record:

```text
Permission to continue: yes / no
Recording allowed: yes / no
Screen or artifact observation allowed: yes / no / limited
Privacy exclusions:
Scheduled stop time:
```

**Gate:** Do not continue without clear permission. Do not place private customer
or company data in `.ROOT`.

## Step 2: Role, Outcome, and Workflow Boundary (Minutes 3-7)

Ask:

1. "What is your role in this process?"
2. "What event starts the process?"
3. "What result means it is actually finished?"
4. "Who receives or depends on that result?"
5. "Which part do you personally perform or control?"

Record:

```text
Participant role:
Trigger:
End condition:
Customer of the workflow:
Participant-controlled steps:
Externally controlled steps:
```

**Most valuable answer:** a narrow boundary such as "new lead arrives to first
qualified appointment" or "field condition discovered to approved change order,"
not "sales" or "project management."

**Gate:** If the workflow cannot be bounded to one trigger and one outcome,
narrow it before continuing.

## Step 3: Anchor to the Last Real Event (Minutes 7-12)

Ask exactly in this sequence:

1. "When did this last happen?"
2. "Which specific lead, job, request, or transaction can we safely use as the
   example?"
3. "What was the first thing you received?"
4. "Where did it appear?"
5. "What did you do immediately after that?"
6. "When and how did this example finish?"
7. "What was different, difficult, or delayed this time?"

Record:

```text
Event date:
Safe identifier:
Starting artifact/tool:
Ending artifact/status:
Elapsed time from trigger to outcome:
Unusual condition:
Evidence available: observed / record / participant recall
```

If the participant generalizes, say:

> Let us stay with that one example. What was on the screen, in the message, or
> in your hand at that moment?

**Gate:** If no event from the last 30 days can be reconstructed, do not proceed
as if the workflow is validated. Choose another workflow or classify the session
as exploratory only.

## Step 4: Show the Work Step by Step (Minutes 12-30)

Say:

> Please replay that example from where it entered. I will ask what happened at
> each step, but I do not want you to clean it up for me.

For every step ask:

1. "What do you do here?"
2. "What information do you need before you can do it?"
3. "Where does that information come from?"
4. "Which tool, screen, document, or message do you use?"
5. "Do you search, copy, retype, download, upload, or reformat anything?"
6. "How do you decide it is correct and ready to move forward?"
7. "Who or what receives it next?"
8. "How do they know it is ready?"
9. "What happens if the next person or system does not respond?"

Fill one row per step:

| # | Actor | Action | Input | Tool | Active min | Wait | Handoff | Evidence O/R/S/I/U |
|---|---|---|---|---|---:|---:|---|---|
| 1 | | | | | | | | |
| 2 | | | | | | | | |
| 3 | | | | | | | | |
| 4 | | | | | | | | |
| 5 | | | | | | | | |

Evidence labels:

- `O` = observed directly;
- `R` = supported by a record or timestamp;
- `S` = participant estimate;
- `I` = interviewer inference;
- `U` = unknown.

**Most valuable answer:** a visible artifact trail that reveals actual tool
switches, waits, and handoffs. The participant's generic description is weaker.

## Step 5: Find the Friction and Exceptions (Minutes 30-37)

Ask:

1. "Where did this example wait?"
2. "Where did you have to chase someone or remember to check back?"
3. "What was entered more than once?"
4. "Where did you search for missing information?"
5. "What was corrected or done over?"
6. "Which step required the most attention even if it took little time?"
7. "What exception makes this process much harder?"
8. "How do you discover something was missed or wrong?"
9. "What judgment or relationship decision must remain human?"

Record the top three only:

| Friction | Step | Evidence | Workaround | Failure or delay caused |
|---|---:|---|---|---|
| | | | | |
| | | | | |
| | | | | |

**Gate:** An annoyance without repeated effort, delay, error, risk, or economic
consequence is not yet a business finding.

## Step 6: Establish Frequency and Magnitude (Minutes 37-43)

For each top friction ask:

1. "How many times did this happen last week? Last month?"
2. "How many total cases go through this workflow in a normal week or month?"
3. "How long does this step take when it goes normally?"
4. "How long did this example take?"
5. "How long does the work wait between steps?"
6. "How many people spend time on it?"
7. "How often does it fail, arrive incomplete, or require rework?"
8. "Which record could verify that number?"

Record:

```text
Cases per week/month:
Friction occurrences per week/month:
Active minutes per occurrence:
Typical wait:
People involved:
Error/rework rate:
Verification source:
Confidence: record / observed sample / estimate / unknown
```

Calculate only when units are defensible:

```text
annual hours = minutes per occurrence / 60 x occurrences per month x 12 x people
annual rework hours = annual cases x error rate x rework hours per error
```

**Most valuable answer:** a system timestamp, calendar, CRM record, invoice log,
job report, or small sample that can replace memory with measurement.

## Step 7: Identify the Consequence (Minutes 43-48)

Ask in this order:

1. "When this is slow or wrong, what happens operationally?"
2. "Who feels the consequence first?"
3. "Does it consume labor, delay cash, risk revenue, create rework, affect a
   customer, or increase compliance/safety risk?"
4. "Tell me about the last time the consequence became material."
5. "What did that event cost in time, fee, delay, lost opportunity, or recovery
   work?"
6. "What happens over the next six months if nothing changes?"
7. "Which part of that cost is known, and which part is only an estimate?"

Record separately:

```text
Labor/capacity consumed:
Direct cost or fee:
Revenue leakage:
Cash-timing delay:
Customer consequence:
Risk exposure:
Known amount:
Estimated range:
Unknowns:
```

**Gate:** Do not add capacity, revenue leakage, delayed cash, and risk into one
headline number. If the economic link is speculative, report the operational
consequence and request the record needed to quantify it.

## Step 8: Prove Existing Motivation (Minutes 48-51)

Ask:

1. "What do you do today to keep this from failing?"
2. "What workaround have you created?"
3. "Have you tried to fix it before?"
4. "What tool, service, staff time, or management attention have you already
   spent on it?"
5. "Why did the prior attempt work, fail, or stall?"
6. "Why has this not been changed already?"

Record:

```text
Current workaround:
Prior attempt:
Time or money already spent:
Reason unresolved:
Constraint: authority / budget / time / data / integration / adoption / other
```

**Most valuable answer:** existing effort or spend. It proves the problem is
important enough to trigger behavior, not merely conversation.

## Step 9: Map Ownership and Buying Authority (Minutes 51-54)

Ask:

1. "Who owns the result of this workflow?"
2. "Who performs the work?"
3. "Who can approve a process change?"
4. "Who controls the relevant system or data?"
5. "Who controls budget?"
6. "Who could block a change even if the owner wants it?"
7. "Who else would need to agree that this is the right diagnosis?"

Record:

```text
Process owner:
Frontline performer:
System/data owner:
Initiator:
Evaluator/influencer:
Gatekeeper:
Decision-maker:
Budget owner:
Likely blocker:
```

For an individual 1099 workflow, distinguish the participant's authority from
the brokerage or platform's authority. Personal pain does not prove company
buying authority.

## Step 10: Try to Disprove Your Diagnosis (Minutes 54-57)

Ask:

1. "When does this process work perfectly?"
2. "Could this be irritating but economically harmless?"
3. "Is the extra step a necessary control rather than waste?"
4. "What would make changing this process a bad idea?"
5. "What important exception have we not discussed?"
6. "Who would disagree with my current interpretation, and why?"

Say your provisional diagnosis:

> The process appears to lose [time/capacity/cash/reliability] at [step], because
> [observed cause]. The strongest evidence is [evidence], while [unknown] remains
> unverified. What did I get wrong?

Record:

```text
Correction from participant:
Necessary control identified:
Counterexample:
Diagnosis after correction:
Confidence: high / medium / low
```

**Gate:** If the participant supplies a strong counterexample, revise or reject
the finding. Do not defend it.

## Step 11: Ask for One Advancement (Minutes 57-60)

Choose the request that resolves the largest unknown:

- observe a second instance;
- review a redacted record or small export;
- interview the upstream or downstream person;
- speak with the owner or decision-maker;
- schedule a dated review of the workflow report;
- scope a paid broader audit when the business evidence qualifies.

Say:

> The most important unanswered question is [unknown]. The smallest next step
> that would answer it is [action]. Are you willing to do that by [date]?

Record:

```text
Requested action:
Owner:
Due date:
Accepted / declined / vague:
Exact commitment:
```

**Most valuable answer:** a dated action involving time, access, data, reputation,
or money. "Interesting," "send me something," and "keep me posted" are not
advancement without an owner and date.

## Vertical Branch: Real Estate

Use only after the universal sequence reveals that the workflow is lead or
transaction related:

1. "Where can a new lead arrive: CRM, phone, text, email, portal, or referral?"
2. "Which channel establishes the official record?"
3. "How is first-response time measured, if at all?"
4. "How do you decide the next follow-up action and date?"
5. "What happens when the lead replies in a different channel?"
6. "How do you distinguish active, nurture, unqualified, and dead leads?"
7. "Which steps are controlled by you, the team, the brokerage, or the platform?"
8. "Can five recent safely redacted leads show response and follow-up history?"

Most valuable real-estate proof: a small, redacted lead sample that shows actual
arrival time, first response, follow-up cadence, disposition, and any manual
reconstruction across channels.

## Vertical Branch: Construction

Use only after the universal sequence identifies the selected workflow:

1. "Where does the lead, bid, field condition, time entry, or billing trigger
   first enter the company?"
2. "What information must be complete before estimating, approval, or billing?"
3. "Who chases missing scope, pricing, photos, labor, or signatures?"
4. "What is entered into more than one of email, spreadsheet, accounting, CRM,
   or construction-management software?"
5. "What waits for owner, project-manager, customer, architect, or subcontractor
   approval?"
6. "How do field records become office records?"
7. "How are exceptions, revisions, and change orders tracked to final billing?"
8. "Can one safely redacted job show the timestamps and handoffs end to end?"

Most valuable construction proof: an artifact-supported path from trigger to
estimate, approval, invoice, or payment showing actual handoffs, waits, duplicate
entry, and decision ownership.

## Ten-Minute Post-Session Scorecard

Complete immediately:

| Required evidence | Result | Strength |
|---|---|---|
| Recent event | | O / R / S / U |
| Workflow observed | | Full / Partial / No |
| Repeated friction | | High / Medium / Low |
| Frequency or volume | | Verified / Estimate / Unknown |
| Consequence | | Verified / Range / Speculative |
| Current workaround | | Strong / Weak / None |
| Prior effort or spend | | Yes / No / Unknown |
| Process owner | | Known / Unknown |
| Decision-maker | | Known / Unknown |
| Advancement | | Dated action / Vague / None |

Classify the session:

```text
ADVANCE = observed recurring pain + credible consequence + real commitment
MEASURE = pain appears real, but magnitude needs one specific record or sample
PARK    = inconvenience with weak consequence, frequency, ownership, or action
REJECT  = presumed problem absent, solved, inaccessible, or not influenceable
```

Strategy evidence:

```text
S-01 willingness to value/pay for observation report:
S-02 real-estate warm-access quality:
S-03 construction credibility/problem access:
Evidence that strengthened an assumption:
Evidence that weakened an assumption:
Next proof, owner, and date:
```

## Interviewer Rules

- Ask about the past before the future.
- Ask "show me" before "how often."
- Follow the artifact rather than rigidly reading every prompt.
- Allow silence; do not answer the question for the participant.
- Do not teach AI, pitch a tool, or design the solution during observation.
- Write facts and estimates separately.
- Stop after one bounded workflow; depth is more valuable than breadth.
- End with a correction and a commitment, not a compliment.

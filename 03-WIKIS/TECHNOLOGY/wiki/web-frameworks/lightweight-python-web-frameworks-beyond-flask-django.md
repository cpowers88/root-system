# Lightweight Python Web Frameworks Beyond Flask/Django

**Summary**: A landscape survey of four WSGI Python web frameworks
positioned as alternatives to Flask and Django — Bottle, Pyramid,
TurboGears, and Falcon — with the specific niche each actually fills.
Note on source style: this book is written as a curated link/resource
directory rather than textbook prose (its own convention throughout), so
this page synthesizes the conceptual framing rather than quoting a
narrative — the source itself is mostly annotated external links.

**Sources**: fullStackPython.pdf (Full Stack Python: 2020 Supporter's
Edition), §4.1 Web Frameworks — Bottle, Pyramid, TurboGears, Falcon
sections.

**Last updated**: 2026-07-13

## Bottle — Single-File, Zero Dependencies

A WSGI framework contained entirely in one source file (`bottle.py`), no
external dependencies beyond the Python standard library. Three specific
good uses, not a general Flask replacement: **prototyping** (skips
Django's boilerplate for a quick idea), **learning how WSGI frameworks
work internally** (the entire framework is one readable file), and small
**personal-project deployment** (drop `bottle.py` alongside your app code
and you have zero deployment dependencies to manage).

## Pyramid — Flexible MVC, Scales Down and Up

A WSGI framework based on Model-View-Controller. Positioned between
Flask's minimalism and Django's full-stack opinion — used for both small
apps and, with its extension ecosystem, larger ones. Notably less
tutorial/community coverage than Flask or Django, so expect more
official-docs reliance than blog-tutorial reliance if picked.

## TurboGears — the XML-Templating, Object-Dispatch Outlier

Can run as either a full-stack framework (Django-like: identification/
auth, autogenerated admin/CRUD, sessions, caching, schema migrations) or a
micro-framework (Flask-like). Two genuinely distinctive design choices:

- **Kajiki templating** — a *validated XML* template engine (unlike Jinja2/
  Mako/Django Templates, which are plain-text). This buys automatic
  HTML-escaping (XSS/injection protection built into the template
  mechanics itself, not bolted on), automatic internationalization
  (the engine can distinguish static text from markup and flag it for
  translation without manual `gettext` wrapping), and WYSIWYG-editor
  compatibility (a valid-XHTML template can round-trip through a visual
  editor).
- **Object Dispatch routing** — instead of regex-based URL routing (the
  Flask/Django norm), a URL path is resolved by literally traversing
  Python objects (`/users/new` → `RootController.users.new`). Very direct
  mapping between URL structure and code structure, at the cost of
  being a genuinely different mental model from every other framework
  covered elsewhere in this wiki.
- Also one of the few Python frameworks with official first-class MongoDB
  support, including admin-panel CRUD generation from MongoDB models.

## Falcon — Minimal, API-Only, No Dependencies

A WSGI framework built specifically for RESTful APIs with no external
dependencies — narrower scope than Bottle (API-only, not general web
apps), optimized for speed (commonly paired with PyPy in the source's own
benchmarking examples).

## Key Ideas

- None of these four displace Flask (already the toolkit-of-record in
  [[flask-web-development]]) for the audit business's near-term client-tool
  needs — they're landscape awareness for when a specific constraint makes
  Flask/Django the wrong fit.
- Bottle's "single file, zero deps" property is the one genuinely
  actionable data point: worth reaching for specifically when a personal
  or throwaway prototype needs to avoid any deployment dependency
  management at all.
- TurboGears' auto-escaping-by-default templating is worth remembering as
  a security-by-construction contrast point against Jinja2's
  manual-escaping-by-convention model, already covered in
  [[flask-templates-and-jinja2]].

## Use / Retrieval Notes

**Use when**: A specific constraint makes Flask/Django the wrong fit — a
truly dependency-free single-file prototype (Bottle), an API-only service
with no HTML rendering (Falcon), or a project that specifically wants
auto-escaping XML templating (TurboGears).

**Do not use when**: The need is a standard client-facing form/dashboard/
portal — Flask, per [[flask-web-development]], remains the right default.

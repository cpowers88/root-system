# Flashcard Batch: Stage 7 — Program Design

## Card: Decomposition

**Front:** What is decomposition, in the program-design sense?

**Back:** Breaking a big problem into smaller, concrete steps that are each simple enough to code directly.

**Tags:** python, stage-07, decomposition

---

## Card: Pseudocode

**Front:** What is pseudocode?

**Back:** A plain-English description of a program's steps, written before any real code, to plan the logic first.

**Tags:** python, stage-07, pseudocode

---

## Card: Flowchart decision shape

**Front:** What shape represents a decision point in a flowchart?

**Back:** A diamond.

**Tags:** python, stage-07, flowcharts

---

## Card: When to use a flowchart

**Front:** When is a flowchart more useful than plain pseudocode?

**Back:** When the logic has several decision points and the branches are getting hard to track in plain English.

**Tags:** python, stage-07, decision-rule

---

## Card: Algorithm

**Front:** What is an algorithm?

**Back:** A precise, step-by-step procedure for solving a problem, independent of which programming language implements it.

**Tags:** python, stage-07, algorithm

---

## Card: Test case

**Front:** Why isn't "it looked right when I ran it" the same as testing?

**Back:** Because that's not a specific, checkable claim — a real test case pairs a specific input with a specific expected output.

**Tags:** python, stage-07, testing

---

## Card: Incremental development

**Front:** Why does building incrementally make debugging easier?

**Back:** Because any new bug is almost always in the one small piece you just added, instead of hidden somewhere in a large block of untested code.

**Tags:** python, stage-07, decision-rule

---

## Card: Decomposition vs. pseudocode

**Front:** What's the difference between decomposition and pseudocode?

**Back:** Decomposition identifies what the smaller pieces are. Pseudocode writes out, in more detail, how each piece works.

**Tags:** python, stage-07, decision-rule

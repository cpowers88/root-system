# `.ROOT` Operating Manual

This is the human operating guide. `START_HERE.md` is the short entrance; `00-BRAIN\AGENT.md` governs AI behavior.

## What `.ROOT` does

`.ROOT` helps Chris:

1. learn difficult material when he needs it;
2. diagnose systems and business workflows;
3. research where valuable problems exist;
4. design and test the smallest useful response;
5. turn verified results into capability, assets, and economic value.

The system stores useful memory and evidence. It does not replace D2L, become a personal taskmaster, or count its own maintenance as North Star progress.

## Operating loop

```text
Outcome → Constraint → Evidence → Smallest Test → Decision Rule → Act → Return
```

For everyday work, simply tell the agent the desired result and available time. The agent should infer the rest and begin. Use the full five-question prompt for uncertain, expensive, or consequential problems.

## Three entrances

### TUTOR

Use for school concepts, practice, explanation, debugging, and retrieval. Name the course and what you need. Chris owns due dates, submission, and D2L truth. Success is independent performance or a diagnosed gap with a re-aimed next rep.

### VALUE

Use for capabilities, technology, business research, workflow diagnosis, tests, and builds. Strategic research narrows from market to reachable workflow and economic consequence. Applied work tests one uncertainty. Success requires stronger evidence, not more pages.

### CASTLE

Use for a system review, conflicting owners, opportunity gate, strategic reconciliation, or a decision about what deserves attention. CASTLE returns one recommendation and its evidence. It does not schedule every day or copy the wikis.

## Current truth

`NOW.md` is the only root current-state page. It names the active lane, current evidence, next action, and any decision Chris must make. It changes only when one of those facts changes.

Owner files remain authoritative:

- North Star and strategy → `01-NORTH_STAR`.
- Subject or professional knowledge → its `03-WIKIS` hub.
- Course sources → `04-SCHOOL` and live D2L.
- Builds → `02-LIBRARY\.PROJECTS` or their external repository.
- Reusable sanitized business assets → `05-BUSINESS`.
- Manual external files and automatic Obsidian clips → `77-INBOX` until routed.
- Placement → `00-BRAIN\WHERE_IT_GOES.md`.

## Evidence ladder

Treat these as different states:

```text
information → understanding → guided performance → independent performance
→ real use → measured outcome → demand/revenue → repeatability
```

Not every task must climb the whole ladder. It must state honestly where it landed.

## Working with multiple agents

Use one lead writer for a live `.ROOT` task. Other agents may research or challenge and return packets; they do not edit the same live owners unless Chris assigns separate boundaries. Consequential work uses an **independent challenger/validator** by default; the lead integrates accepted evidence.

## When records are required

Write to an owner when reality changed. Create a DAILY or handoff only when meaningful continuity, a decision, evidence, a blocker, or a system change would otherwise be lost. Routine conversation and every minor task do not require their own ceremony.

## Reviews

- **On demand:** school planning, system diagnosis, or opportunity decision when Chris asks.
- **Monthly:** reconcile capability, value evidence, current strategy, CASTLE, and system friction.
- **Quarterly:** run the North Star Ratchet and decide whether to keep, narrow, or replace the current vehicle.

No standing Sunday school plan or automatic evening-reading assignment is required. A dated review or test exists only when it has an owner, evidence target, and decision rule.

## Safety and authority

Chris approves external messages, publication, spending, credentials, private/client data use, destructive action, new durable commitments, and governance changes. AI never enters `88-JOURNAL`, never writes under `raw`, and archives approved retirements instead of deleting them.

Active client-specific work stays in a **separate client workspace outside `.ROOT`**. Only approved sanitized learning, non-sensitive metadata, and reusable assets return.

## System health

Run `python 00-BRAIN\scripts\root_health.py` after governance or system changes. Its result verifies named technical properties. Practical health is separate: the system must help Chris begin faster, produce proof, preserve truth, and spend little time managing itself.

## Stop rule

If `.ROOT` creates two owners, hides the next action, invents school certainty, confuses output with proof, or consumes more effort than the work it supports, stop expanding it. Diagnose the runtime and simplify the smallest responsible layer.

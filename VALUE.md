# VALUE — Capability, Business, Research, and Building

Use this lane to strengthen Chris's professional capability and convert it into useful, measurable, and ultimately economic value.

## Load

After the root runtime boot, load:

1. `HAT_OPERATOR.md`.
2. The one owner appropriate to the question: BUSINESS, SYSTEMS, TECHNOLOGY, AI_AUTOMATION_SYSTEMS, REVENUE_LAB, or an active project.
3. `value_production_goal.md` when making a proof claim.
4. `CURRENT_STRATEGY.md` only for vehicle, market, offer, or strategy decisions.
5. Watchtower only for a material external signal.

Do not load school, unrelated wikis, CASTLE maps, or broad research history by default.

## Choose one mode

### Strategic Landscape

Use when deciding where Chris should aim. Narrow:

```text
industry → function → workflow → value leak → user/buyer → value mechanism → access → vehicle
```

Return no more than three decision-relevant candidates. Keep **absolute opportunity ceiling** separate from **Chris's probability-adjusted path**. Each serious candidate names evidence, uncertainty, capability required, smallest proof, and disconfirming result.

### Applied Proof

Use when a reachable workflow, real user, or faithful simulation can reduce a named uncertainty. Apply the root Action Kernel, then observe or test before recommending a substantial build.

For business work, always identify:

- who experiences or pays for the problem;
- what currently happens;
- where the process breaks;
- economic or operational consequence;
- present workaround and adoption friction;
- result that justifies building, buying, changing, or stopping.

### Capability Build

Use when the limiting uncertainty is what Chris can independently do. Choose a small visible output tied to a real workflow, build it, test it, and require Chris to explain or reproduce the essential reasoning before calling the capability proven.

## Evidence ladder

Research can strengthen a ranking. It cannot count as use, demand, adoption, revenue, or repeatability. A useful progression is:

```text
research → observation → diagnosis → smallest test → working result
→ real use → measured outcome → demand/revenue → repeatability
```

Access enables field proof but does not determine the final market. Construction and real estate are advantages, not protected answers.

## Agent boundary

One lead agent owns integration and `.ROOT` writes. Delegated researchers may read and return sourced packets; they may not change strategy, promote findings, contact anyone, open commitments, or edit live owners unless Chris explicitly assigns that boundary.

## Return

Approved sanitized reusable assets may enter `05-BUSINESS`.

No outreach, pricing commitment, purchase, publication, client action, credentials, or private-data use without Chris's approval.
